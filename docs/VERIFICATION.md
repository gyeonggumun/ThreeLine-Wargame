# 분석 방법과 검증 범위

## 자료와 역할 정보

| 출처 | 용도 |
| --- | --- |
| `sub3th_제출용.ova` | 제출 VM의 실제 애플리케이션·서비스·계정·권한·네트워크 설정 확인 |
| 제공된 워크스루 PDF | 38페이지의 전체 문제 설명과 기존 실습 결과 확인 |
| 본인 설명 | 5인 팀의 팀장, Challenge 1·2 담당, SSH·방화벽·sudo·파일 권한·계정 및 문제 간 접근 통제 수행 |

문서 안의 명령과 안내는 과거 실습 설명으로 읽었습니다. 이 분석을 수행하라는 지시로 취급하거나 공격 명령을 실행하지 않았습니다.

## 수행한 분석

1. OVA의 OVF, VMDK, 매니페스트 구성을 확인했습니다.
2. OVF와 VMDK의 SHA-1을 매니페스트와 비교해 일치를 확인했습니다. 이는 배포본 내부의 일관성 확인이며 배포자 신원이나 보안을 인증하는 절차는 아닙니다.
3. streamOptimized VMDK의 압축 grain을 읽기 전용으로 해석하고 GPT·ext4에서 관련 파일을 읽었습니다.
4. 담당 앱의 두 라우트, 템플릿, Apache 프록시, systemd 서비스, UFW, SSH, sudo, 계정·그룹 및 관련 파일 모드를 확인했습니다.
5. 담당 문제의 워크스루 1~6페이지는 텍스트와 렌더링 화면을 함께 검토했습니다. 전체 문제 구성은 38페이지의 추출 텍스트와 관련 구현을 대조했습니다.
6. 담당 앱이 참조하는 진행도 완료 API를 추가로 확인해 서명·플래그 검증과 공유 키 권한을 분석했습니다.

## 증거와 주장 연결

| 기술 설명 | 증거 |
| --- | --- |
| SQL 문자열 결합과 응답 분기 | `app.py`의 `ch1_login()` |
| 셸 명령 주입 구조 | `app.py`의 `ch2_webhook()` |
| 담당 앱 localhost 바인딩 | `app.py`의 마지막 실행 설정 |
| 서비스 계정·실행 제한 | 두 systemd 서비스 원본 |
| Apache 요청 분기 | VirtualHost의 ProxyPass |
| 수신 기본 차단과 열린 포트 | UFW 기본값·user.rules·user6.rules |
| SSH 제출 상태 | 메인 활성 지시문·포함 파일·UFW |
| 계정 로그인 제한과 그룹 | `/etc/passwd`, `/etc/group`의 관련 항목 |
| 문제 및 키 파일의 접근 범위 | ext4 inode의 UID·GID·mode |
| 기존 플래그 획득 결과 | 담당 문제 워크스루 3·6페이지 |

공개하는 원본 파일의 SHA-256과 권한은 [evidence.json](evidence.json)에 있습니다. `app.sanitized.py`는 DB 비밀번호 한 값을 치환한 사본이며 원본 해시와 공개 사본 해시를 구분했습니다. 그 외 참조 파일은 추출 바이트를 유지했습니다.

## 수행하지 않은 검증

- VM 부팅, 실제 포트 스캔, SSH 로그인, 공격 및 플래그 재획득
- 실행 중 UFW·iptables 규칙, `sshd` 실효 설정, systemd 실제 상태 확인
- MariaDB 실행 중 레코드·GRANT·계정별 실효 권한 조회
- 모든 문제 소스와 OS 전체의 보안 감사
- 문제 간 접근 차단이나 외부 통신 통제의 실제 성공·실패 시험

따라서 **설정 존재**, **기존 워크스루에서의 실행 성공**, **현재 실행 검증**을 구분해서 서술했습니다. 성공률·응답 성능·완전 격리와 같은 측정되지 않은 성과는 기재하지 않았습니다.

## 원본 자료의 해석 보정

- HTTP 500은 SQLi의 단독 확정 근거가 아닙니다. 쿼리 생성 소스와 조건에 따른 응답을 함께 확인했습니다.
- User-Agent가 curl이라는 사실만으로 명령 주입이 성립하지 않습니다. `shell=True`와 입력 결합 코드를 확인했습니다.
- Base64는 암호화가 아니라 인코딩입니다.
- 2번 문제의 일반 화면은 stdout을 직접 표시하지 않지만, 실패 API는 detail을 반환하는 분기가 있습니다.
- 표준 sudo 규칙이 있다고 서비스 계정에 sudo 권한이 있는 것은 아닙니다. 계정의 그룹과 개별 허용 규칙을 구분했습니다.
- `nologin`, localhost 바인딩, `PrivateTmp`, `NoNewPrivileges`는 서로 다른 경계를 다루며 완전한 샌드박스를 보장하지 않습니다.

## 공개 제외 항목

OVA·가상 디스크·원본 PDF, DB 비밀번호, 플래그 값, HMAC 키, 로그인 세션, 참가자 진행도 데이터, 관리자의 개인 파일과 호스트 식별 정보는 업로드하지 않습니다. 키와 플래그는 기술 설명에 필요한 파일 경로와 권한만 기록했습니다.

이 저장소에는 전체 DB·정적 자원·모든 팀 문제·자동 구축 절차가 포함되지 않습니다. 따라서 전체 실습 환경의 완전 재현을 제공한다고 설명하지 않습니다.
